# Skill 目录说明

本目录是从「单导联心电监测前端」开发过程中沉淀下来的可复用经验。
每一项都写明了**适用范围、使用方法与失效条件**，目标是：一支陌生队伍拿到本目录，
换一个题目、换一块板卡，仍能直接使用。

## 逐项说明

### 1. `pitfalls.md` —— 踩坑清单

- **适用范围**：Vivado 工程管理、Simulation、IP 打包、AXI 互连、定点 DSP、PYNQ 上板。
  与本项目无关的条目已单独标注。
- **使用方法**：遇到报错或异常现象时先全文搜索关键词（如 `WNS`、`DMA`、`0x00`）。
  每条含「触发条件 → 现象 → 根因 → 定位方法 → 修法」。
- **已验证效果**：本项目在最后 10 天里靠它避免了重复踩坑；
  其中「0x00 寄存器双用途」「Overlay 复位」「DMA 步长」三条被反复引用。
- **失效条件**：条目依赖于 Vivado 2025.2 / 2026.1 与 PYNQ 2.7 的行为；
  工具大版本变化后部分结论需重新验证。

### 2. `prompt_workflows.md` —— 提示词工作流

- **适用范围**：任何用大模型辅助做 RTL 设计、上板调试、文档写作的场景。
- **使用方法**：按「任务类型」选模板，替换 `{{...}}` 占位符后使用。
  每个模板都附了「为什么这样写」与「常见失败模式」。
- **已验证效果**：本项目 80% 的 RTL 与脚本由这套流程产出；
  其中「判据先行」模板使返工率显著下降（详见 `docs/llm-collab.md`）。
- **失效条件**：模板假设模型具备长上下文与代码执行反馈能力；
  纯问答式模型上效果会打折。

### 3. `templates/overlay_bringup.py` —— Overlay 上板模板

- **适用范围**：任何 PYNQ 工程，首次把比特流跑起来并确认寄存器可读写。
- **使用方法**：改 `BIT` 路径与 `VERSION_ADDR` 两处常量，直接运行。
- **已验证效果**：本项目每次换比特流都跑它，成功拦下过 2 次「比特流与 hwh 不匹配」。
- **失效条件**：要求设计里有版本寄存器；
  若没有，脚本会退化只做 Overlay 加载与地址可访问性检查。

### 4. `scripts/bitstream_identity.py` —— 比特流身份校验

- **适用范围**：同一块板反复换比特流的场景（本项目换了 20+ 次）。
- **使用方法**：`python3 bitstream_identity.py <bit文件> <版本寄存器偏移> <期望值>`
- **已验证效果**：本项目用它确认「板上跑的是 `0xEC600008`」而不是旧比特流，
  避免了至少 3 次「改了 RTL 但板上没变」的误判。
- **失效条件**：需要设计内有只读版本寄存器；没有则只能比对文件 MD5。

### 5. `pynq_generic/SKILL.md` —— 通用 PYNQ Skill

- **适用范围**：**任何** PYNQ / Zynq 项目的上板启动与排障，不依赖本项目任何模块。
- **使用方法**：按其中的 8 步流程执行；每步都有「通过判据」与「失败怎么办」。
- **已验证效果**：本项目从「Overlay 加载成功」到「能稳定读回数据」的调试时间
  从最初的两天压缩到最后的两小时。
- **失效条件**：面向 PYNQ 2.7（Linux 5.15）验证；PYNQ 3.x 的 `pynq.Overlay`
  接口有变化，需替换为 `pynq.Overlay(bitfile)` 的新写法。
