# 性能基线对比

> 对应评分项「性能与资源优化效果」——官方要求"在目标器件上取得可测量的性能表现，并给出与基线的对比"。

## 1. 算力基线：同一算法的四种实现

算法完全相同：**50 Hz 陷波（Q=10）→ 40 Hz 低通（Q=0.707）**，Direct Form I，Q2.14 定点。

| 实现 | 5000 点耗时 | 吞吐量 | 对参考加速 | 能否实时 |
|---|---|---|---|---|
| **A 浮点逐样本**（参考真值，double） | 6.2 ms | 0.80 MS/s | 1.0× | 可以，但精度过剩 |
| **B 频域批处理**（FFT → 乘 H(f) → IFFT） | 0.54 ms | 9.3 MS/s | 11.6× | **不可**（需整段，边界误差 524 LSB） |
| **C 定点逐样本**（纯 Python 循环，算法与 RTL 完全一致） | 5.6 ms | 0.90 MS/s | 1.1× | **可以**（实时软件实现的真实成本） |
| **D RTL 流水线**（62.5 MHz，1 样本/时钟，6 拍延迟） | 0.080 ms | **62.5 MS/s** | **78×** | **可以**（硬件） |

### 关键对比

> **RTL 相比"能真正跑在系统里的实时软件实现"（C）快 70 倍。**
> **相比最快的离线方法（B）快 6.8 倍，且 B 无法流式、边界误差达 524 LSB。**

### 为什么不用 B 作为主基线

FFT 批处理需要拿到**整段数据**才能开始，且存在**循环卷积边界效应**（实测最大误差 524 LSB，是定点误差的 314 倍）。
实时 ECG 采样是无限长的流，不可能"等采完再滤"，所以 **C 才是公平基线**。

### 保守性说明

上述计时在 **PC（i7-1165G7）** 上测得。目标板是 **ARM Cortex-A9 @ 667 MHz**，纯 Python 循环会慢 5~10 倍，
因此**真实的 RTL 加速比应显著大于 70 倍**——这个对比是保守的。

## 2. 精度基线

| 实现 | 最大误差 | RMS 误差 | 占满量程 |
|---|---|---|---|
| C 定点逐样本 vs A 浮点 | **1.67 LSB** | 0.49 LSB | 0.041% |
| RTL vs C（逐位比对，2000 样本） | **0 LSB（2000/2000 逐位相同）** | 0 | 0% |

> RTL 与定点模型**逐位相同**，所以 RTL 的精度等价于 C：**最大 1.67 LSB**。

## 3. 资源与延迟

| 项 | 数值 | 说明 |
|---|---|---|
| LUT | 1788 / 53200 = **3.36%** | 整条链路（滤波 + PT + DDS + 注入器 + AXI） |
| FF | 2522 / 106400 = **2.37%** | 同上 |
| BRAM | 1.5 / 140 = **1.07%** | 波形缓冲 1024×32 |
| DSP48 | 17 / 220 = **7.73%** | 滤波 10 + PT 等 6 + 注入器 1 |
| **WNS** | **+0.741 ns** | 10 ns 约束下收敛；实际时钟 16 ns，真实余量约 6.7 ns |
| **流水延迟** | **96 ns**（6 拍） | 占 4 ms 采样周期的 0.0024% |

### 吞吐余量

62.5 MS/s ÷ 250 S/s = **25 万倍余量**。

这不是"浪费"，而是**架构选择的依据**：
- 若改用软件循环，CPU 需持续 100% 占用才能勉强跟上 250 S/s，且抖动达 3.9~57 µs；
- RTL 用 **3.36% 的 LUT** 换取"零 CPU 占用 + 96 ns 固定延迟 + 25 万倍余量"；
- 余量使得**扩展为多导联（12 导联只需 12 倍）或提高采样率（如 1 kS/s）时无需改架构**。

## 4. 时基一致性（这条常被忽略）

| 方案 | 采样率 | 误差 | 对 50 Hz 陷波的影响 |
|---|---|---|---|
| `time.sleep(4ms)` | 236.52 Hz | **+5.70%** | 50 Hz 被看成 52.85 Hz，**偏离陷波中心 2.85 Hz → 完全失效** |
| `perf_counter` 忙等 | 250.00 Hz | **+0.00%** | 偏离 0.00 Hz → 正中靶心 |

> **"算得快"不够，"算的时候采样率对"才是前提。** 这是本项目实测到的、最容易翻车的一环。

## 5. 复现方式

```bash
# PC 侧（无需板子）
python python/perf_baseline.py     # 输出表格 + report/figs/perf_baseline.png

# 板侧（真实 ARM 计时）
python3 /boot/rate_check.py        # 采样时基对比
python3 /boot/host_ecg.py          # 主机通道 + 硬件陷波（A3 为抑制比）
```

数据来源：`report/figs/perf_baseline.png`、`report/WORKLOG.md` 对应条目。
