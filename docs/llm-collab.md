# AI 协作报告

> 项目：ECG-DDS-FPGA —— 基于 PYNQ-Z2 的心电信号处理链路
> 周期：约一个半月，自初版系统（V1~V4）至板级验证完成
> 本文记录 AI 在项目中被使用的范围、承担的工作、产生的错误与代价，
> 以及人机双方的分工如何随事故不断收紧。

---

## 零、概述

项目分四个阶段：

| 阶段 | 时间 | 目标 | 交付 |
|---|---|---|---|
| **P1 初版系统** | 第 1~2 周 | 打通 DDS 波形 → AXI 寄存器 → PS 回读 | V1~V4，23 条设计决策 |
| **P2 架构升级规划** | 第 3 周 | 对照评分表审计初版，定六层目标架构 | 四条约束、七条不足、技术栈图谱 |
| **P3 核心算法硬件化** | 第 4~5 周 | Pan-Tompkins、定点滤波链、XADC 通路 | PT 20/20、2000/2000 逐位一致 |
| **P4 板级验证与真实信号** | 第 6 周 | 上板、时序收敛、抑制比、真实采集 | −68.5 dB、0.00% 时基误差 |

最终交付：RTL 1687 行 / 9 个模块，仿真 12 个脚本与 12 个 testbench，板端 17 个脚本，
设计决策 23 条，开发日志 28 条目 / 50 KB，重建 6 次。

## 一、AI 的使用范围

| 环节 | 由 AI 承担 | 由人工承担 |
|---|---|---|

| Testbench 与仿真 | 全部 12 个 testbench 与运行脚本 | 判断仿真是否覆盖关键路径 |
| 板端脚本 | 全部 17 个验收脚本 | 在板上执行、回报现象 |
| 时序收敛 | 违例归因、流水线拆分方案 | 判断改动是否改变算法 |
| 文档与决策记录 | 体例设计、正文撰写 | 条目结构、判断依据的最终确认 |

## 二、提示词与要求的演进

协作方式并非一开始即如此，而是在四次事故中逐步收紧。以下为要求层面的前后对比
（依据 `report/working_agreement.md` 的编号条款与增补记录）。

### 2.1 从"给出结论"到"给出可复核的证据"

- **早期做法**：要求 AI 核对代码改动是否落实，AI 返回核对表并标注通过。
- **事故**：有一次核对针对的文件在磁盘上并不存在，AI 仍标注通过；
  该缺陷（`reg_wave_addr` 无驱动）一路带到综合阶段，由 `Synth 8-3848` 警告暴露。
- **收紧后的要求**（§2.5，编号条款 R1–R5）：每条结论必须附 `grep`/`read` 的原文行号；
  要核对 N 项即须出示 N 条证据；未出现者必须写"未找到"；不得由"已下指令"推断"已存在"。
- **效果**：此后所有源文件结论均可回溯到行号，未再出现无证据的通过标记。

### 2.2 从"能跑"到"测法与判据先行"

- **早期做法**：让 AI 给出可运行的脚本，按输出判断好坏。
- **事故**：抑制比实测 −3.4 dB，与仿真预期相差 12 倍。两轮修改脚本均无效
  （等待时间 2.5 s → 5.0 s；注入幅度校核），最终发现失效的是**测量方案**而非设计。
- **收紧后的要求**：任何指标必须同时给出**判据**与**测量方式**，
  且测量方式本身须先被验证（例：以纯正弦检验幅度提取函数，输入 600 LSB 测得 600.3 LSB）。
- **效果**：抑制比在修正后的测法下测得 −68.5 dB，与此前的 −3.4 dB 属不同测量对象。

### 2.3 从"接近"到"等价"

- **早期做法**：以"误差在可接受范围"作为结构改动的验收标准。
- **问题**：拆流水线后，误差小与算法退化在数值上难以区分。
- **收紧后的要求**：任何结构变更后，须先重跑 `compare_rtl.py`，要求
  **2000/2000 逐位相同、偏移 +0**，方可重建；并以偏移扫描（−3..+3）排除整体错位。
- **效果**：三次重建中功能零回归。

### 2.4 从"给代码"到"讲清命令与原理"

- **早期做法**：直接给出可执行的命令串。
- **要求**（§2.6，编号条款 C1–C6）：每条命令须说明工具用途、各选项含义、各参数含义，
  涉及危险操作须标注后果；新概念须先给定义、量纲与本项目中的取值。
- **效果**：板端调试中能自行判断异常输出的含义，而非逐条回问。

## 三、AI 承担的工作与其价值

以下六项为 AI 在本项目中产生的实质性贡献，均附可核查证据。

### 3.1 把"不可实现"论证成结论，并给出替代架构

滤波链原设计含 0.5 Hz 数字高通。该级极点半径 0.9911，导致
`A(1) = 1 + a1 + a2 = 1.565e−4`，输出量化误差经反馈环放大 6389 倍。

AI 未直接下结论，而是实现并实测四种方案，全部不达 2 LSB 判据：

| 实现 | 实测输出误差 |
|---|---|
| 16 位截断 | 3198 LSB（发散） |
| 16 位四舍五入 | 729 LSB |
| 内部 Q14 精度 | 17 LSB（乘法器需 26 位） |
| 一阶 DC 阻断 | 140 LSB |

随后提出并实施**功能重新分配**：基线漂移由模拟前端高通、PT 内部带通、
PS 侧软件去基线三者共同承担。这不是"修实现"，而是改变功能归属。

### 3.2 建立数值等价性基线

Python 定点模型（Q2.14、Direct Form I、`(acc+8192)>>>14`、状态饱和）先行实现，
RTL 随后按同一算法编写，实测与模型 **2000/2000 逐位相同、偏移 +0**；
偏移 ±1 时一致率降至 10.76%，证明并非巧合对齐。

该基线的价值在于：此后任何结构改动都可在数分钟内判定"算法是否被改"。

### 3.3 时序违例的归因

滤波链首次重建 WNS 为 −6.363 ns、289 个端点违例。AI 的分析路径为：
**前 8 条最差路径全部源自同一单元 `u_filt/s2_p2`** → 问题归一化到单一模块 →
拆为三级流水（乘法 / 加法树 / 移位饱和），并将饱和比较位宽由 36 位降至 22 位
（右移 14 位后仅剩 22 位有效）→ WNS +0.741 ns。

### 3.4 把物理量换算成功能结论

采样实现由 `time.sleep(4ms)` 改为忙等后，AI 给出的不是"精度提高"，而是换算链：

```
实测采样率 236.52 Hz（偏差 +5.70%）
   → 50 Hz 干扰在滤波器视角下位于 52.85 Hz
   → 陷波 −3 dB 带宽仅 48.11~51.91 Hz（±1.9 Hz）
   → 偏移 2.85 Hz 已出带 → 抑制功能完全失效
```

该换算把"3% 的采样率误差"转换为"功能失效"，使修改的紧迫性有据可依。

### 3.5 可观测性设计

Pan-Tompkins 检测数停滞时，AI 提出并实现两级观测手段：
将 PT 内部滑动和写入波形缓冲的调试通道（回读得 `max = 395139`，每 206 点一峰）；
以及在检测时刻写入 `0x8000 | r_index`（回读得 82/289/495/702，与黄金参考偏差 ≤1）。

约十余行 RTL 的成本，将"检测链是否工作"与"是否漏检"两个问题同时排除，
使排查范围收敛到时基层。

### 3.6 决策记录体例

初版阶段即确立单一决策的记录格式：**备选方案 → 选择 → 量化依据 → 代价 → 为何可接受**，
累计 23 条（`report/design_decisions.md`，428 行）。该体例使"为什么不选另一个"
成为可核查内容，而非事后追述。

## 四、AI 的错误与代价

AI 的错误并非随机，集中在四类。以下按类型列出，均附发现方式。

| 类型 | 案例 | 代价 | 发现方式 |
|---|---|---|---|
| **幻觉** | 核对表标注通过，但被核对的文件不存在 | 缺陷带至综合阶段 | `Synth 8-3848` 警告 |
| **机制误判** | 未核验 `.gen` 缓存，综合使用了落后 18 分钟的旧副本 | 一次无效构建 | 源文件与缓存的时间戳比对 |
| **推理失效** | 整机冻结事件中连续提出六个假设并逐个修改，全部失败 | 约一个工作日 | 最终以 xsim 复现板级时序后定位 |
| **推理失效** | 抑制比 −3.4 dB 归因于"缓冲未刷新" | 一轮脚本修改 | 等待时间延长后读数基本不变 |
| **推理失效** | 自相关峰值 0.237 判定为存在心搏 | 一轮分析 | 折叠平均后幅度等于噪声平均本底 |
| **推理失效** | 周期扫描所得 52.2 码判为有效心电 | 一轮分析 | 波形宽度为 QRS 的 7.6 倍且顶部平坦 |
| **事实错误** | 默认 PS 时钟为 Block Design 所配的 100 MHz | 约三小时排查 | 三个独立量交叉验证为 62.5 MHz |
| **数字不自洽** | 决策 D-20 称读取"快 3000 倍"，按给出的绝对值应为 13600 倍 | 需补勘误 | 用同一公式反算 |
| **算法缺陷** | EDR 输出恰为真实呼吸率的 2 倍 | 一轮修正 | 注入已知量的判据检出错在二次谐波 |

### 4.1 三类错误的成因

**幻觉类**源于"以陈述替代证据"。AI 在无原文行号的情况下仍会给出确定的结论，
其概率与上下文长度正相关。对策不是要求"更仔细"，而是要求**格式化的证据**
（行号、哈希、时间戳）。

**机制误判类**源于"不验证工具行为"。构建产物的缓存、比特流的路径、
寄存器的复位状态，这些不体现在源码中的事实，AI 默认其符合常识。
对策是将核验步骤写入流程（`working_agreement.md` §3.5 的 G1–G5）。

**推理失效类**源于"沿错误假设生成自洽论证"。这是 AI 最稳定的行为特征：
给定假设后，它能给出高质量的推导，但不会自发检验假设本身。
本项目七次由数据推翻其结论，均属此类。

## 五、人工介入及原因

| 介入类型 | 具体情形 | 原因 |
|---|---|---|
| **物理操作** | 焊接、面包板接线、换卡、上电、量电压、贴附电极 | AI 无法接触物理世界；其判断依赖人工回报的数据 |
| **方案取舍** | 否决引入 HLS 以"补齐技术栈"；否决 DMA 的第一次判断后又重新采纳 | AI 无工期压力，倾向"增加"而非"取舍" |
| **结论采纳** | 七次以数据推翻 AI 结论 | AI 会沿错误假设继续论证 |
| **标准制定** | 逐位相同、注入已知量、抖动阈值、单频激励 | AI 的默认验收标准是"结果合理"，过宽 |
| **安全判断** | 人体实验的可行性与中止条件 | 不可委托 |

其中**方案取舍**一项值得单独说明：AI 曾提议以 HLS 与 DMA 补齐技术栈。
该提议在第一次判断中被否决，理由是原始波形数据率仅 500 B/s，
DMA 的固定开销高于其吞吐收益。此后重新评估时发现该判断遗漏了"采样时刻的控制权"维度，
结论随之修正。**两次判断均有量化依据，修改结论的原因是依据不完整，而非立场变化。**

## 八、经验

**有效的用法**：

1. 要求 AI 给出**可被证伪的假设**，而非结论。本项目多次靠此将可能性集合缩小到单一原因。
2. 要求**换算**：把参数偏差换算为功能影响（3% 采样率误差 → 陷波失效），
   使修改有据。
3. 要求**逐位等价**而非误差范围。这是唯一能区分"结构优化"与"算法退化"的标准。
4. 要求**格式化的证据**（行号、时间戳、哈希）。"已检查"不是证据。

**无效的用法**：

1. 让它"继续优化"——没有判据时，它会持续增加内容。
2. 以单次读数下结论——它会为单一读数构造自洽解释。
3. 以"看起来对"验收——形态相似不能排除系统性偏差。

**一句话**：模型在给定问题内足够强，但它不会检验问题本身。
因此协作的效率取决于**问题与判据的质量**，而非提示词的措辞。
