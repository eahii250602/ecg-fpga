# 大模型协作记录

## 一、分工的实质

本项目由单人完成，周期约四周。引入大模型的目的不是补足人手，而是补足并行的思考与实现能力。

但协作的实质并非按工种切分。真正的分界在于：
**模型能够在给定问题内给出高质量的解，但它不会替你决定什么值得做、什么算做完、凭什么说做对了。**

这三件事贯穿整个项目，且在每一个节点上都被重新明确过一次。本文记录的是这一过程，
以及它如何决定了项目的技术形态。

---

## 二、把工程目标转述为可证伪的命题

模型对"做一个心电采集系统"的默认理解，是交付一条能出波形、能测心率的链路。
按这个标准，项目在第三周就能"完成"。

但"能出波形"不是可检验的目标。本人将目标重述为四个并列命题，并要求每一项给出数值与取得方式：

| 命题 | 判定方式 |
|---|---|
| 算力上是否值得用硬件实现 | 与同算法的实时软件实现比较吞吐量 |
| 定点化是否损失了算法 | 与浮点参考比较误差；与定点模型逐位比较 |
| 时间基准是否成立 | 实测采样率与抖动 |
| 生理量是否算得对 | 注入已知参数，检验能否还原 |

这一转述改变了后续所有工作的性质：**每个模块在实现之前，必须先回答它改善上表中的哪一项。**
无法回答的模块不予实现——这正是后来否决若干技术栈提案的依据。

同样的转述也决定了创新点的选择方式。当发现"创新性"是最薄弱的一项时，
可选方向并不少（边缘推理、自适应滤波、多导联、信号质量评估），
本人的筛选条件不是"哪个更前沿"，而是三个必须同时成立的条件：

1. 有本项目自身的证据支撑其必要性；
2. 有可说明的应用价值；
3. 能在剩余工期内完成**可证伪的验证**。

据此选定单导联三参数方向：项目中反复出现"数据不可信而无法判断"的情形，构成第 1 条；
一条导联输出三个生理参数可省去独立呼吸传感器，构成第 2 条；
以注入已知参数的方式验证，构成第 3 条。

## 三、验证标准的先行设定

模型默认的验收方式是"结果合理"。本项目的验收标准由本人先行设定，再要求实现去满足：

| 标准 | 被拒绝的替代方案 | 理由 |
|---|---|---|
| 结构变更后与定点模型**逐位相同** | "误差在可接受范围" | 无法区分结构优化与算法退化 |
| 算法正确性以**注入已知量**验证 | "波形形态正确" | 形态相似不能排除系统性偏差 |
| 采样抖动 **< 16 ns** | "差不多够用" | 抖动直接决定滤波器频率响应的有效性 |
| 抑制比以**单频激励**测量 | 以"心电 + 干扰"的混合信号测量 | 混合信号的频谱泄漏会掩盖真实抑制比 |

标准先于实现，其后果是明确的：滤波链在第一次重建时因时序不收敛被退回，
在第二次重建前须先通过逐位比对；抑制比的测量方案在得出异常结果时先被推翻重做，
而非修改设计。这些返工不是效率损失，而是标准生效的证据。

## 四、工期约束下的取舍

单人四周的工期决定了必须放弃一部分"看起来完整"的工作。

**技术栈的完整性不作为目标。** 竞赛指南列举了 HLS、AXI-Stream、DMA 等方向，
但指南同时明确要求避免"以显著的资源代价换取有限的性能收益"。
本项目的算法为固定系数 IIR，手写 RTL 的可控性高于 HLS，故未采用 HLS。

**AXI DMA 的判断经历过一次修正，且两次判断都有量化依据。**
第一次判断为不采用：原始波形数据率 500 B/s，DMA 的固定开销高于其吞吐收益。
第二次判断为采用：该结论仅计入吞吐量，遗漏了更关键的维度——**采样时刻的控制权**。
项目中已实测软件定时造成采样率偏差 5.70%，使 50 Hz 陷波完全失效；
即便改用高精度忙等，抖动仍由操作系统决定。只要采样时刻由软件决定，该缺陷无法根除。

结论的修正并非立场反复，而是**反对意见必须给出量化依据**这一要求的结果：
当依据被证明不完整时，原结论即失效。

**时间分配按确定性排序。** 文档、记录、基线对比这类产出确定性强，
优先完成；功能扩展与架构变更风险高，置于其后并单独重建。
项目另设"单一问题不超过 30 分钟"的约束，避免局部问题吞噬整体工期。

## 五、裁决

模型的一个稳定特征是：**在给定假设下生成自洽的解释**。
这使得它在假设错误时不会停顿，而是沿着错误方向继续给出高质量论证。
因此本项目的推进方式，是由本人以测量数据对模型结论作出裁决。

全周期共七次：

| 模型结论 | 推翻依据 |
|---|---|
| 抑制比为 −3.4 dB，原因是缓冲未刷新 | 延长等待时间后结果不变 |
| 206 码的落差值即为心电幅度 | 频谱主成分位于 0.17~0.83 Hz，属基线漂移 |
| 自相关峰值指示存在心搏 | 折叠平均后幅度等于噪声平均本底 |
| 周期扫描所得 52.2 码为有效心电 | 波形宽度为 QRS 的 7.6 倍，且顶部平坦 |
| 寄存器写入失败，疑为总线故障 | 版本寄存器读回值指向旧版比特流 |
| 时基抖动判据为 50 µs | 该判据无物理依据，换算后 57 µs 对应相位噪声 1°，可忽略 |
| 呼吸率估计已正确 | 注入 15 次/分而算出 30.0，为二次谐波 |

这些裁决构成了项目的主要推进方式。模型提供假设与实现，本人提供反例与判据。

## 六、能力转移

单人项目的风险不在进度，而在**判断力集中在模型一侧**：一旦无法评估其输出，
项目即失去控制。因此协作方式本身被设计成能力转移机制。

具体做法有三：概念先行（任何新概念须先给出定义、量纲与本项目中的取值，方可进入实现）；
命令逐条讲解（每条命令须说明工具、选项与参数含义，而非仅给出可执行的字符串）；
判断留痕（每个决策须记录依据、备选方案与被否定的理由）。

《协作约定》以编号条款的形式固定了上述规则，并规定其增补方式：**每一次事故转化为一条规则。**
该文件与约 50 KB 的开发日志共同构成可核查的过程记录，其体例由本人设定并持续维护。

这一机制的目标不是"学会使用工具"，而是**在项目结束时具备独立判断同类问题的能力**。
