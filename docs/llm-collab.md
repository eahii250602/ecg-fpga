# 大模型协作记录

## 一、周期与约束

项目周期约一个半月，自方案设计至板级验证。协作贯穿全过程，其形态由本人在项目初期设定的
四条硬性约束决定：

1. 必须是**架构**层面的升级，不为凑数增加小功能；
2. 须有**真实社会应用价值**；
3. 每项优化必须**由已发现的具体不足驱动**，不为炫技增加内容；
4. 技术栈须**完整覆盖**（不止 RTL + PS/PL 两层）。

上述约束的作用不是表达愿望，而是**排除一整类提案**。模型在没有约束时倾向于给出"可增加的功能清单"，
四条约束将讨论的上限从"还能加什么"压到"哪个不足尚未解决"。
本文后续所有判断均可追溯到其中某一条。

## 二、自我审计：由七个不足导出路线

项目第二阶段（约第六周）对既有系统做过一次系统审计，逐项对照评分表定位差距。
审计结论不是"还差哪些功能"，而是七条带证据的不足：

| # | 不足 | 现状证据 | 评分影响 |
|---|---|---|---|
| 1 | 自闭环：波形由 DDS 产生、再由自身检测 | 无真实输入 | 创新性与应用价值 30 |
| 2 | 计算负载近似为零 | 每 4 ms 一次 12 位比较，DSP 0 个 | 同上及性能 20 |
| 3 | 波形数据走控制通道 | 1024 点 = 2048 次 MMIO 事务 | 性能与资源 20 |
| 4 | 检测器过于简化 | 固定阈值 + 200 ms 不响应期 | 功能正确 20 |
| 5 | `rr_count` 实测与理论矛盾 | 51 vs 理论 206 | 功能正确 20 |
| 6 | 软件栈单薄 | 仅 Python 读取寄存器 | 功能完整 20 |
| 7 | 交付物空白 | README / 提交包 / 开源 / 协作记录未动工 | 文档与协作 30 |

由此形成六层目标架构：采集（模拟前端 + XADC）、处理（PL 定点滤波与检测管线）、
传输（AXI-Stream + DMA）、系统（Linux 侧记录与报警）、智能（HRV 指标与规则筛查）、
自检（DDS 改造为可编程信号源与干扰注入器）。

**该审计的关键作用**：它把"升级"从一个开放问题变成了有限问题。
此后每一项工作都对应表中某一条；无法对应的工作不予立项。

## 三、决策的记录体例

早期即确立单一决策的记录格式：**备选方案 → 选择 → 量化依据 → 代价 → 为何可接受**。
至第四阶段累计 23 条，形成可复核的决策链。以下三条可说明该体例的约束力：

**D-02（相位截断）**：32 位相位累加器若全精度寻址，ROM 需 4G 点；
截断为 8 位地址后仍保有 0.023 Hz 频率分辨率，ROM 降至 256 点（3 Kbit）。
选择由"分辨率需求"倒推出"可截断位数"，而非先定结构再补理由。

**D-08（除法不外移硬件）**：心率数秒更新一次，实时性要求低，
硬件除法占用 DSP 且压缩时序余量，故除法置于 PS 侧。
该决策的实质是**按更新频率而非按功能划分归属**。

**D-20 及其勘误 E-01（读取方式）**：原记录称"读取 1024 点需 0.3 ms，比采样速度快 3000 倍"。
该数字只计 AXI 硬件协议耗时，遗漏 Python 每次 `mmio` 调用的 0.5~2 µs，
2048 次调用实际为 1~4 ms；且 4096 ms ÷ 0.3 ms ≈ 13600，与文中"3000 倍"不自洽。

勘误给出的更正不是替换数字，而是确立一条校验规则：
**给出的倍数必须能由给出的绝对值用同一公式推出**。
此后所有对比数据均须满足该闭合条件，否则视为未完成论证。

## 四、收敛式排查

项目中若干疑难问题的解决方式具有共同结构：**假设集逐步缩小，直至只剩一种可能**。
这与试错不同——每一步都在排除一个维度，而非随机更换方案。

### 4.1 检测器"漏拍"（约三小时，五次假设）

| 轮次 | 假设 | 否证依据 |
|---|---|---|
| 1 | 输入序列或相位不合适 | 以板级精确样本流与四种相位偏移仿真，均 20/20 通过 |
| 2 | 判定在平顶样本上失效 | 改为阈值穿越后仿真全通过，板级检测数仍为 3 |
| 3 | 检测链停止 | 经调试通道回读滑动和：`max = 395139`，每 206 点出现清晰峰，链正常 |
| 4 | 检测事件被丢弃 | 事件打标回读 `r_index = 82/289/495/702`，与黄金参考偏差 ≤ 1，未丢弃 |
| 5 | 采样时基错误 | `Clocks` 读数 62.5 MHz；20 秒检测数对应 44.95 BPM；每拍 206.5 点反推 154.7 Hz。三者一致 |

第 5 轮之后，可能集只剩"文档所载 100 MHz 从未在运行时生效"一种：
PS 侧 FCLK 由启动镜像 `ps7_init` 写寄存器确定，`.bit` 不改变 PS 时钟。
修正 `TICK_DIV` 与全部频率字后问题消失。

该过程的价值在于第 3、4 轮的观测手段：它们不是为主假设服务的，
而是**为排除整个"算法层"的可能性**而设计。观测通道的成本约十余行 RTL。

### 4.2 抑制比异常（−3.4 dB，与仿真差 12 倍）

两次否证后才收敛到唯一原因：

| 假设 | 否证依据 |
|---|---|
| 环形缓冲未刷新 | 等待时间由 2.5 s 改为 5.0 s（> 4.096 s 整圈）后，读数由 297.4/202.0 变为 298.1/202.38，未改善 |
| 注入幅度仅为设定值的一半 | 以纯正弦检验测量函数本身：输入 600 LSB 测得 600.3 LSB，函数正确 |
| 心电峰值与注入叠加后饱和削顶 | 关闭心电（`FTW = 0`）仅保留纯正弦，抑制比测得 −68.5 dB |

唯一原因由三个测试缺陷叠加构成：心电峰值已达 12 位上限导致饱和削顶；
R 波窄脉冲的频谱泄漏落于 50 Hz 附近；缓冲窗口未覆盖完整周期。
**滤波器自始至终正常，失效的是测量方案。**

两次排查的共同点：**先验证测量手段，再怀疑被测对象**。
这一顺序在硬件项目中不是保守，而是必要——测量链路本身有两个不可见环节（工具与测试条件）。

## 五、技术栈的补齐

竞赛指南列举的 AXI-Stream、DMA、HLS 三项在本项目前四阶段尚未落地，
其原因不是评估后舍弃，而是**排期在后**：先建立可验证的处理核心，再补传输与实现方式。

当前已确定三者的功能落点，且划分依据为数据形态而非工具可得性：

| 技术栈 | 承担功能 | 划分依据 |
|---|---|---|
| AXI-Stream | 逐样本顺序流（采样节拍 → DMA） | 顺序数据天然是流式语义 |
| AXI DMA | DDR 环形缓冲（64 k 样本 ≈ 256 s） | 唯一能将采样时刻由软件转交硬件的机制 |
| HLS | SQI 的多频点能量核 | 算法密集、系数需迭代，可直接复用定点模型作对账参考 |
| RTL | 滤波、检测、滑动窗、导联合成 | 结构固定，要求确定性延迟 |

即 **RTL 负责"流"，HLS 负责"算"，PS 负责"判"**。
该划分已完成方案设计并通过评审，进入实施阶段。

## 六、关于协作方式的说明

协作用于扩大单位时间内的实现与论证能力，其有效性取决于两点：

其一，**问题必须由本人定义**。四条约束、七条不足、六层目标架构均出自项目自身的审计结果，
而非模型的能力清单。模型在此框架内提供方案与依据，超出框架的提案不予采纳。

其二，**结论必须由本人裁决**。模型在给定假设下会生成自洽的论证，
即便假设错误也不会停顿。因此推进方式为：模型提供假设与实现，本人以测量数据裁定取舍。
全周期被数据推翻的模型结论共七项，逐条记录于开发日志。

这两点决定了项目的技术形态：它由一组被验证过的判断构成，而非由一组被实现过的功能构成。
