## 二、关键参数（写 Python / 上板要用）

```
   IP 基地址        : 0x43C00000
   地址范围         : 64 KB (0x10000)
   PL 时钟 FCLK_CLK0: 100 MHz
   采样率           : 250 Hz（tick_gen 分频值 400000）
   寄存器映射       :
        0x00  W  FTW         频率控制字 → 改心率
        0x04  W  WAVE_ADDR   波形读地址（0~1023）         ★V4
        0x08  R  RR_COUNT    RR 采样点数
        0x0C  R  WAVE_DATA   该地址处的波形值（32位有符号）★V4
        0x14  R  VERSION     0xEC600001（AXI 通路自检）
   心率换算         : BPM = 60 × 250 / rr_count
   FTW 换算         : FTW = 2^32 × (BPM/60) / 100e6

   上板三件套（都在 D:\ecg\board\，必须放板子同一目录）：
        bit\ecg_bd.bit         4,045,769 B（★与 .hwh 同名配对）
        bit\ecg_bd.hwh           139,294 B
        python\ecg_monitor.py   Python 上位机脚本
```

截断到 12 位 = **48** → P 波/QRS/T 波全超阈值 → 每拍 3 次检测。
板上 51 与 104 正是循环 {51,51,104.5} 的成员（51+51+104.5 = 206.5 ✓）。

**修复**：`component.xml` 仅两处（dataType→integer、加 format="long"），**RTL 一字未动**。
备份 `component.xml.bak_20261023`。⬜ **待：Vivado 刷新 IP → 验证包装层无引号 → 重建 → 上板复测。**

**教训（与 L-14 同族）**：历次仿真都直接例化 RTL 传数值参数，恰好绕过「BD 包装层→比特流」路径——
**验证必须覆盖真实例化链，单元对 ≠ 系统对。**
