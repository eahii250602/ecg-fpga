# 单人作战执行方案（solo_plan.md）

> 背景：**2026-10-23 确认队友全部退赛**，项目由 1 人独立完成（大一学生，板级操作者）。
> 本文件**替代** `sprint_2weeks.md` 第四节的"三人分工"，是排期与取舍的依据。
> 与 `master_plan.md` 的关系：P0~P5 的**目标不变**，但时间与范围按单人重排。

---

## 一、先把现实约束说透

| 约束 | 实际情况 | 影响 |
|---|---|---|
| 时间预算 | **工作日 2h + 周末每天 8h = 26h/周，两周 ≈ 52h**（2026-10-23 用户确认） | 三人版（≈100h+）仍需砍半，但比 36h 版宽松 44% |
| 无法并行 | Vivado GUI、重建比特流（15 min/次）、上板、接线、万用表全在一人手上 | 串行瓶颈——**大块板级操作集中排在周末**，工作日只做轻量验证 |
| 学习成本 | 定点滤波、Pan-Tompkins、DMA、AXI-Stream 都要边学边做 | 多出的 16h 优先给**缓冲与深度**（更好的权衡表、更好的文档），不扩范围 |
| 单点故障 | 生病/考试/断电**无人替补** | 每个阶段结束都必须是**可提交状态** |
| 行政 | ✅ **组委会确认允许单人**（2026-10-23） | 无阻碍；报名名单按组委会流程变更即可 |

> 结论：**不要试图"把三人的活一个人做完"，而是"把能被 AI 承包的活全部交出去，自己只保留不可替代的部分"。**

## 二、分工重构：AI 承包 vs 你必须亲手做

### 2.1 AI 全包（你只需：粘贴 → 运行 → 把真实输出贴回来）

| 类别 | 内容 |
|---|---|
| RTL 源码 | FIR/IIR 滤波、Pan-Tompkins 检测、XADC DRP 控制器、AXI-Stream、DMA 集成、报警逻辑 |
| 测试台与仿真 | 全部 testbench；**AI 能在自己环境跑 xvlog/xelab/xsim 并给结论**（不必你跑） |
| Python | 离线黄金参考算法、上位机脚本、绘图、HRV 统计、报告生成 |
| 文档 | README、报告、`pitfalls.md`、`prompts/`、技能包、复现指南 |
| **Vivado Tcl 脚本** | BD 加 IP/连线/地址/生成、综合实现启动、报告导出（见第三节） |

### 2.2 你必须亲手做（不可替代，约占你全部时间的 60%）

1. **板级操作**：接线、电极、分压、万用表、SD 卡拷贝、跑脚本、把输出原文贴回
2. **Vivado GUI**：Tcl 覆盖不到的动作；点"Generate Bitstream"；等 15 分钟
3. **决策与验收**：判据是否达成、方案取舍、要不要降级（**只有你能签字**）
4. **学习**：读逐行讲解、自己复述一遍——这是竞赛里"你的能力"那部分，AI 不能替你答辩

## 三、关键杠杆：把 Vivado 操作脚本化（Tcl）

单人最大的浪费是"一个人在 GUI 里点半天 + 等重建"。对策：**凡能用 Tcl 的都用 Tcl**。

| 动作 | Tcl 化 | 收益 |
|---|---|---|
| BD 加 IP / 连线 / 分地址 | `create_bd_cell`、`apply_bd_automation`、`assign_bd_address`、`validate_bd_design`、`save_bd_design` | 你只需在 Tcl Console 粘一次（我会逐行注释） |
| 重建 | `reset_target` / `generate_target` / `launch_runs impl_1 -to_step write_bitstream` | 一次启动，不用点 |
| 报告导出 | `report_utilization`、`report_timing_summary` 等 | 归档自动化（G4） |

**纪律**：Tcl 也必须**逐行讲解**后再给你（协作约定 §2.6 不变）；Tcl 里任何**改 IP/参数**的动作仍要遵守 L-08（Vivado 关闭状态下改）与 L-13。

## 四、砍单清单（按"分数÷成本"排序的取舍）

| 项 | 原计划（三人版） | **单人版** | 理由 |
|---|---|---|---|
| P1 真实采集 | AD8232 + XADC | **保留**（核心叙事） | 创新 30 的主干，砍了项目就散了 |
| P2 滤波链 | 高通 + 50Hz 陷波 + 带通 | 保留（陷波可先做一阶，够用再加阶） | 功能 + 性能 |
| P2 权衡实验 | 位宽 / 窗长 / 通道 ×1/2/4/8 | **位宽 + 窗长两张表保留**；通道扩展**只做仿真**不流多套比特流 | 性能 20 看的是对比与论证，不是比特流数量 |
| P2 PT 检测 | 完整流水线 II=1 | 算法功能完整保留，**流水线只求 II≤2** | 时间；可写进"权衡"里解释 |
| P3 DMA | AXI-Stream + DMA | **保留**（性能分主力，实测倍数） | 43.9ms → <5ms 是最硬的数字 |
| P3 systemd 自启 | 开机自启服务 | **降级**：脚本 + 说明 + 半自动 | 演示收益低、调试成本高 |
| P3 板载网页 | 可选 | **砍** | 高分成本，低分收益 |
| P4 HRV | SDNN/RMSSD/pNN50 | 保留 SDNN/RMSSD，pNN50 可选 | 两个指标已够讲故事 |
| P4 报警 | 多规则 + LED | 保留 1~2 条规则 + LED 演示 | 演示够了 |
| P4 LLM 报告 | 自然语言筛查报告 | **保留**（协作 15 分 + 应用叙事） | 性价比最高的一项 |
| 12 导联 / 上云 / CNN / CDC | 不做 | 不做 | master_plan 已定 |

**降级顺序（一旦超时，按此顺序砍）**：板载网页 → systemd → 通道扩展实验 → pNN50 → 陷波阶数 → 演示剧本华丽度。
**绝不能砍的底线（P1 + 一张权衡表 + DMA 对比数字 + README/技能包）**——这四样直接对应 30+20+20+30 分。

## 五、节奏与缓冲（按"工作日 2h / 周末 8h"两种模板）

### 工作日（2h，轻量日——不碰大改造）

```
   0:00~0:20  板级快检（跑脚本、贴输出、看判据；不重建）
   0:20~1:40  AI 产出审阅 + 验证（读讲解、跑仿真结果、决定是否降级）
   1:40~2:00  归档 + 明日准备
```

### 周末（8h，大块日——集中做需要重建/接线/调试的事）

```
   第 1 小时  启动重建/长仿真（等待型任务先启动）
   第 2~3 小时  等待期间：审阅 AI 产出 + 学讲解
   第 4~5 小时  板级操作（上板、接线、跑判据）
   第 6 小时    午休/缓冲
   第 7~8 小时  归档 + 下一步准备 + 复述（检验自己是否真懂了）
```

## 七、答辩叙事的变化（这是加分点，不是减分点）

原计划是"3 人大一团队"。现在诚实且有力地讲法是：

> "**1 名大一学生，通过与 AI 深度协作，独立完成从模拟前端采集、FPGA 硬件滤波与 QRS 检测、
> DMA 数据通路，到 HRV 分析与 LLM 筛查报告的完整边缘心电监护原型。**"

把它落成证据：`skill/pitfalls.md`（工具链坑与破案过程）+ `prompts/`（怎么指挥 AI 干活）+ Tcl 自动化脚本。
这正是"**大模型协作与技能包 15 分**"要的东西——而且比三人分工的版本更能说明协作深度。
唯一要注意的是**别虚报**：答辩时如实说明队友退赛后独立完成，重点讲方法（怎么协作、怎么验证）。
