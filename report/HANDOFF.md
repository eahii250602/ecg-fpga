### 3.2 第一版完整项目的体系结构（数据流）

```
   PS(ARM/Linux) ──AXI4-Lite──▶ IP 寄存器
        │  写 0x00 FTW  ──▶ DDS 相位累加器(32bit) ──▶ 取高 8 位查表
        │                                              │
        │                                    ecg_rom (256×12, 偏移二进制, 2048=基线)
        │                                              │ 12bit 波形
        │                                    tick_gen (100MHz ÷ 400000 = 250Hz)
        │                                              │
        │                              ┌───────────────┴───────────────┐
        │                              ▼                               ▼
        │                    r_detect(阈值1200+200ms静默)      波形写入环形缓冲
        │                              │                        (1024×32bit, BRAM)
        │                    rr_counter 数两 R 峰间 tick 数            │
        └── 读 0x08 RR_COUNT ◀─────────┘                              │
        └── 写 0x04 WAVE_ADDR / 读 0x0C WAVE_DATA ◀───────────────────┘
                        ▼
              Python: BPM = 60 × 250 / rr_count，画心电图，存 CSV/PNG
```

### 3.3 寄存器映射（**最常用，务必记牢**）

```
   基地址 0x43C00000，范围 64KB，PL 时钟 FCLK_CLK0 = 100 MHz，采样率 250 Hz
     0x00  W  FTW         频率控制字（改心率）
     0x04  W  WAVE_ADDR   波形读地址 0~1023
     0x08  R  RR_COUNT    RR 采样点数（16 位，D-09）
     0x0C  R  WAVE_DATA   该地址波形值（32 位有符号，低 12 位有效）
     0x14  R  VERSION     0xEC600001（AXI 通路自检）
   读通道用 axi_araddr[4:2] 做多路选择
   换算：BPM = 60 × 250 / rr_count ；FTW = 2^32 × (BPM/60) / 100e6
         FTW=52 → 72 BPM ；FTW=43 → 60 BPM（rr_count 理论值 206.5 / 249.7）
```

### 3.5 上板环境事实（踩过坑，务必遵守）

## 4. 重大 Bug 与修复（按严重度）

### 4.1 L-15 · IP 参数被包装层当【字符串】传给 RTL（2026-10-23 破案，静默失效）★ 最重要

- **现象**：板上 `rr_count` = 51 / 104，而理论值 206.5（差约 2~4 倍），但波形完全正常。
- **三层破案**：① 静态排查排除 8+ 个假设（缓存 md5 / XCI 参数 / tick 逻辑 / 读通道 / 时钟数学 / ROM 双峰 / PHASE_W / FTW）；② 判别仿真 `tb_rr_check.v`（数值参数）证明 RTL 完全正确（208/209 与 83/84，符合理论）；③ 复现仿真 `tb_rr_str.v`（把 `.THRESHOLD("1200")` 写死）→ THRESHOLD 例化成 **48**，rr_count 循环 {51, 51, 106}，**板上现象 100% 复现**。
- **根因**：`parameter signed [11:0] THRESHOLD` 被 IP 打包器归为**向量型** → BD 包装层渲染成 `.THRESHOLD("1200")` → Verilog 把字符串 `"1200"`（= 32'h31323030）截断到 12 位 = **48** → P 波(+54)/QRS(+2047)/T 波(+451) 全部超阈值 → 每拍检出 3 次，循环 {51, 51, 104.5}，而 51+51+104.5 = 206.5 ✓。
- **修复（三处缺一不可，RTL 逻辑一字未动）**：

| 位置 | 改动 | 作用 |
|---|---|---|
| `ecg_axi.v` L10 | `parameter signed [11:0] THRESHOLD = 12'sd1200,` → `parameter integer THRESHOLD = 1200,` | Vivado 按 HDL 声明推导参数类型 |
| BD 实例的 `*.xci` L18/L27 | 两处 THRESHOLD 补 `"format": "long"` | **包装层渲染成数字的直接开关**（决定性） |
| `component.xml` | dataType→integer、value 加 `format="long"` | 防以后重新打包再犯 |

- **代价教训**：只改 `component.xml` 无效；只改 HDL 声明也无效；**XCI 的 `format` 才是开关**。另外：历次仿真都直接例化 RTL 传数值参数，恰好绕过"BD 包装层→比特流"路径——**单元对 ≠ 系统对，验证必须覆盖真实例化链**。
- **板上实测（判据全达成）**：`rr_count` 51/104 → **207**（理论 206.5，差 0.2%）；实测 BPM 294.12 → **72.46**（目标 72，误差 0.64% = 量化极限）；波形 min/max/mean −381/2047/111.5 不变；`fix_test` S9~S13 写读全正常；S14=80 是启动瞬态（复位→首个 R 峰 81 tick），非 bug。
- **修复后新比特流**：MD5 `24CC59A7E90B08CC621814CA85C53735`（旧 `1AD3C0B6…`），LUT 528 / FF 663 / BRAM 1 / DSP 0，时序全过，WNS +3.94ns。

### 4.2 L-14 · AXI 写握手「通道顺序」死锁（2026-10-11 修复，历时半个月）

- **现象**：任何 AXI 写操作都会挂死总线（读正常），板上耗时半月未解。
- **根因**：从机对写地址/写数据/写响应三通道的到达顺序处理不当，形成握手死锁。
- **修复**：重写从机写通道状态机（2026-10-11）。
- **板上确认**：2026-10-23 `fix_test.py` 的 S10「写操作返回了！」+ 回读 `0x00=43`、`0x04=5` 全对，**零冻死**。
- 详细版见 `landmines.md` §L-14。

### 4.3 L-13 · `Clocks.fclk0_mhz` 会把 PL 超频到 160MHz（2026-10-23）

### 6.3 目标架构（升级后全景）

```
【采集层】电极 → AD8232 模拟前端 → Zynq 片上 XADC（12bit）→（J5 排针，见第 8 节）
```
