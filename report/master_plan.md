# ECG-DDS-FPGA v2.0 · 架构升级总计划（master_plan.md）

> **版本**：定稿 v1.0（2026-10-23）
> **性质**：竞赛项目总体升级路线图，此后所有工作以此为准
> **设计约束**（用户四条硬性要求）：
> 1. 实质上的**架构**升级，不为凑数加小功能
> 2. 有**真实社会应用价值**，结合前沿领域
> 3. 每项优化必须**由已发现的不足/问题**驱动，不为炫技加东西
> 4. 技术栈要**丰满**（不止 RTL + PS/PL），且大一学生通过与 AI 协作**可实现**

## 一、现有系统的七个真实不足（一切升级的出发点）

| # | 不足（现状证据） | 后果 | 对应评分损失 |
|---|---|---|---|
| 1 | **自闭环**：DDS 自己造心电、自己检测自己 | 无真实输入 → "心电监测"叙事不成立 | 创新性与应用价值 30 |
| 2 | **计算负载≈0**：每 4ms 一次 12 位比较（DSP 0 个，LUT 0.99%） | "为什么必须用 FPGA"回答不了 | 同上 + 性能 20 |
| 3 | **数据通路走控制通道**：1024 点 = 2048 次 MMIO 事务，实测 45.2ms/4KB | 波形数据用寄存器轮询搬运，架构上就是错的 | 性能与资源优化 20 |
| 4 | **检测器是玩具**：固定阈值 1200 + 200ms 不响应期 | 真实心电的基线漂移 / 50Hz 工频 / 肌电噪声会让它直接失效 | 功能正确 20 |
| 5 | **rr_count 实测与理论矛盾**（51 vs 理论 206，两轮证据打架待判别） | 核心输出"心率"的正确性存疑 | 功能正确 20 |
| 6 | **软件栈薄**：只有 Python 读 /dev/mem | "嵌入式系统"层面（启动、驱动、数据流、服务形态）几乎空白 | 功能完整 20 |
| 7 | **交付物空白**：README / 提交包 / 开源 / 协作记录 / 技能包全未动工 | 30 分（15+15）没入账 | 文档 15 + 协作 15 |

> ★ 本计划每一阶段都从上表某条不足出发。**没有一条升级是"为了加而加"。**

## 二、目标架构（升级后的全景）

```
【采集层】 电极 → AD8232 模拟前端 → Zynq 片上 XADC（12bit 1MSPS）
              │
【处理层】 PL 数字滤波管线：直流去除(高通) → 50Hz 陷波 → 带通
              → Pan-Tompkins QRS 检测（微分/平方/滑窗积分/自适应双阈值）
              → RR 间期 / HRV 统计 / 报警判定
              │
【传输层】 AXI-Stream → AXI DMA(S2MM) → DDR（替代寄存器轮询）
              │
【系统层】 PS Linux：Python 分析 / 落盘记录 / 报警输出 / 开机自启（systemd）
              （可选）板上网页实时波形
              │
【智能层】 HRV 指标 + 心律失常规则筛查 + LLM 生成自然语言筛查报告
              │
【自检层】 DDS 保留 → 改造为"可编程信号源 + 噪声/干扰注入器"
           （既当自测试源，又给滤波管线制造真实敌人）
```

**与现状的本质区别**：从"寄存器轮询的自闭环演示"变成
**"真实心电采集 → 硬件实时处理 → DMA 数据通路 → Linux 分析报警"的边缘心电监护原型**。

## 四、六阶段计划（每阶段结束 = 一个可提交的完整状态）

### P0 · 正确性收尾（约 1 次工作 · 已在执行）

- **驱动它的不足**：#5 rr_count 矛盾（51/104 vs 理论 206.5，两轮证据打架）
- **任务**：
  1. 跑"峰间隔判别实验"（数 CSV 里的 R 峰位置）→ 一刀切开"DDS 快 4 倍"还是"检测器连发"
  2. 定位根因并修复（该改 RTL 就改，走 G1/G2 重建纪律）
  3. 动态心率全表验证：写 FTW=43/52/87/130 → BPM 应得 60/72/120/180
  4. 波形 PNG + CSV 归档（V4 实测证据）
- **评分**：功能正确 20 分的地基
- **你将学到**：判别实验设计（一次实验同时杀死多个假设）

### P1 · 真实信号入口（约 2~3 次工作）= 项目质变点

- **驱动它的不足**：#1 自闭环 → 无应用价值
- **任务**：
  1. 【第一步，必做】核对 PYNQ-Z2 官方原理图：确认 Arduino 座 A0~A5 是否连到 Zynq XADC 辅助通道（及通道号）
  2. 采购 **AD8232 单导联心电模块**（约 ¥30~60）+ 电极片/导联线（**马上下单，物流与调试并行**）
  3. 电平适配：AD8232 输出 0~3.3V，XADC 量程 0~1V → 设计分压电阻（模拟功课）
  4. BD 加入 XADC（向导模式），把真实心电采进 PL
  5. 用现有波形缓冲看到**第一帧真实心电**（里程碑）
- **回退路径**（风险已预案）：
  - XADC 未引出 → 换 SPI ADC PMOD（走 SPI 主机 RTL，反而多学一个接口协议）
  - 采购来不及 → 走 P2 的"噪声注入"路线仍完整成立（DDS 变成可编程干扰发生器）
- **评分**：应用价值 30 分的主力
- **你将学到**：读原理图、datasheet、量程/参考/分压、真实生物电信号长什么样

### P2 · 硬件处理管线 + 权衡实验（约 3~4 次工作）= 性能分主战场

- **驱动它的不足**：#4 检测器是玩具 + #2 负载≈0
- **任务**：
  1. **先让旧检测器"当场失效"**：把真实心电（或注入噪声的合成信号）喂给固定阈值检测器，记录失败现象 → 这就是升级的正当性证明（问题驱动的实证）
  2. RTL 实现定点滤波链：直流去除（高通 ~0.5Hz）→ 50Hz 陷波 → 带通
  3. Pan-Tompkins：5 点微分 → 平方 → 滑动窗积分 → 自适应双阈值 → 峰值定位
  4. 先仿真对照 Python 参考实现（同一输入逐点比对误差）→ 再上板
  5. **权衡实验表（20 分的直接材料）**：
     - 定点位宽：12 / 16 / 24 bit → 资源 vs 检测精度
     - 滑窗长度：50 / 100 / 150 点 → BRAM vs 响应
     - 通道复制 ×N（N=1/2/4/8）：LUT/FF/BRAM/DSP/Fmax 扩展曲线（标注"1 真实 + N-1 自检通道"，诚实呈现）
  6. 实时性论证：每样本固定 N 周期（可数）vs 软件 WCET 无界（Linux 非实时）→ 确定性论证而非吞吐吹嘘
- **评分**：性能与资源优化 20 + 功能完整
- **你将学到**：定点 DSP、流水线、资源/时序报告解读、如何做一张像样的对比表

### P3 · 数据通路与系统集成（约 2~3 次工作）

- **驱动它的不足**：#3 轮询 45.2ms/4KB + #6 系统形态空白
- **任务**：
  1. 波形出口改 **AXI-Stream**，BD 加 **AXI DMA（S2MM）** 写 DDR
  2. **前后对比实测**（我们已有"前"：45.2ms/1024 点）→ 拿到"后"的数据 → 报告里写"提速 X 倍（实测）"
  3. Linux 侧：systemd 开机自启采集服务、数据按时间戳落盘
  4. （可选，有余力）板起个小 HTTP 服务，浏览器看实时波形（演示杀手锏）
- **评分**：功能完整 20 + 性能 20 的实测数字
- **你将学到**：流式总线、DMA、中断/完成同步、嵌入式产品形态

### P4 · 智能分析与价值层（约 2~3 次工作）

- **驱动它的不足**：只报一个平均心率，临床筛查价值太薄
- **任务**：
  1. HRV 时域指标：SDNN / RMSSD（真实临床指标，硬件算 RR 序列、Python 统计）
  2. 心律失常规则筛查：心动过缓 / 心动过速 / 早搏疑似（RR 突缩短）→ 报警位 + LED
  3. 演示剧本：设 180BPM → 板上报警灯亮 + 屏幕提示（应用价值的直观证据）
  4. **LLM 协作落地**：特征数据 → 自然语言"筛查报告"生成；把本次协作全过程（含 6 个错误假设的复盘）整理成《大模型协作记录》
- **评分**：创新与应用 30 + 大模型协作 15
- **你将学到**：HRV 含义、规则系统、把 LLM 嵌进工程流程的正确姿势

### P5 · 工程交付（约 2 次工作）

- **驱动它的不足**：#7 交付空白（30 分没入账）
- **任务**：
  1. 仓库结构：`src / sim / build / board / data / skill / report / README`
  2. README（一页讲清：干什么/为什么/怎么复现/结果数据）
  3. MIT 开源 + LICENSE + 复现指南（从空工程到出图）
  4. skill 技能包：`pitfalls.md`（已有，扩写）+ `prompts/`（怎么让 AI 干活的经验）
  5. 清理：绝对路径（L-02）、提交包只留一份源码（L-01 的最终解决）
- **评分**：文档 15 + 协作 15 全入账

## 五、明确不做的事（防凑数纪律）

| 不做 | 理由 |
|---|---|
| CNN / 量化推理加速器 | 工程量≈现有项目 3 倍；大一时间线下必然烂尾；炫技风险 > 收益 |
| 多时钟域 200MHz + CDC | 没有真实需求（当前 WNS +3.938ns 裕量充足）；CDC 是调试黑洞 |
| 以太网 / 上云 | 链路调试成本高、演示收益低；板上网页（P3 可选项）已够 |
| 12 导联真实硬件 | 电极工程量与成本大；单导联 + N 通道扩展论证已足 |
| 为占资源而堆逻辑 | 评委要的是**权衡论证**，不是占用率 |
