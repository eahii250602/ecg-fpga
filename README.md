# ECG-DDS-FPGA

**基于 PYNQ-Z2（Zynq-7020）的心电信号采集与处理链路：RTL 定点滤波、Pan-Tompkins R 波检测，
以及心率 / 心率变异性 / 呼吸率三参数的硬件辅助提取。**

---

## 1. 项目概述

本设计在可编程逻辑（PL）内实现三段硬件功能：可编程心电波形源、两级 IIR 定点滤波链、
Pan-Tompkins R 波检测器；并配套波形缓冲、版本自证寄存器、以及一条将外部采样样本注入硬件链的通路。
处理器系统（PS）侧以 Python 完成参数配置、指标计算与运行决策。

设计的核心目标不是"能出波形"，而是**对链路的算力、数值精度、时间基准与生理量正确性
四个维度分别给出可测量的指标，并说明每一项的取得方式与代价**。四项指标及其证据见 §4。

---

## 2. 设计约束

心电信号的物理特性决定了本设计必须满足的三个条件：

| 约束 | 物理事实 | 对本设计的要求 |
|---|---|---|
| **干扰远大于信号** | 体表心电约 0.3~2 mV，工频共模干扰可达数百 mV | 须在 50 Hz 处取得 ≥ 40 dB 抑制 |
| **信号能量集中在低频** | QRS 波主能量位于 5~15 Hz | 通带须覆盖 5~15 Hz，高频段须抑制肌电 |
| **采样节拍必须准确** | IIR 频率响应以采样率为坐标 | 采样率偏差须小于 1%，否则陷波中心偏离 |

第三条在本项目中曾造成实质性失效：采样率为 236.52 Hz（偏差 +5.70%）时，
50 Hz 干扰在滤波器视角下位于 52.85 Hz，超出陷波 −3 dB 带宽（48.11~51.91 Hz），
抑制功能完全丧失。详见 §5.5。

### 3.1 总体数据流

```

                    │                ├──▶│ noise50 │─▶│ ecg_filt │─▶│pt_chain│─▶ RR
  内部波形源         │  ┌──────────┐ │   │ 注入器  │  │ 陷波+低通│  │ PT 检测│   心率
  ecg_rom(256×12)   │  │ dds_ecg  │─┘   └─────────┘  └────┬─────┘  └────────┘
                    │  └──────────┘                        │
                    │                              ┌────────▼────────┐
                    │                              │ 波形缓冲        │
                    │                              │ 1024×32 BRAM    │
                    │                              └────────┬────────┘
                    └───────────────────────────────────────┼──────────┘

                                                  ┌─────────▼─────────┐
                                                  │ PS：Python / PYNQ │
                                                  └───────────────────┘
```

### 3.2 三个硬件模块

**心电波形源（dds_ecg）** 采用 32 位相位累加器扫描 256 点心电模板表，心率由频率字 `FTW` 控制：

```
每拍采样点数 = 2³² / (FTW × TICK_DIV)      TICK_DIV = 62.5 MHz / 250 Hz = 250 000
FTW = 83 → 206.99 点/拍 → 72.5 BPM
```

选择频率字而非文件回放的依据是：检测器验证需在 72.5~179.9 BPM 区间做连续扫频（§6），
频率字可单参数调节，文件回放则需为每个心率重新生成数据。

**滤波链（ecg_filt）** 为两级 IIR biquad 级联，Direct Form I，系数格式 Q2.14。
第一级为 50 Hz 陷波（Q = 10，−3 dB 带宽 48.11~51.91 Hz），第二级为 40 Hz 低通（Q = 0.707）。
每级拆为三级流水（乘法 / 加法树 / 移位与饱和），总延迟 6 拍 = 96 ns。

**R 波检测（pt_chain）** 实现 Pan-Tompkins 五步：5~15 Hz 带通、微分、平方、150 ms 滑动积分、
自适应阈值判峰。其带通与积分环节以串行 MAC 实现，依据见 §5.4。

### 3.3 软硬件功能划分

| PL 承担 | PS 承担 |
|---|---|
| 采样节拍生成、滤波、R 波检测 | 寄存器配置、波形回读 |
| 输出 RR 间隔、检测计数等已降维特征 | HRV（SDNN / RMSSD / pNN50）计算 |
| 波形缓冲（1024×32 BRAM） | EDR（心电衍生呼吸率）计算 |
| | 依据信号质量做置信判断 |

划分原则为：**PL 输出已降维的特征量，PS 只做统计与决策，不参与实时数据搬运。**
该原则的直接后果是原始波形不进入 PS 数据通路，因此本设计未采用 DMA；
但该结论仅计入吞吐量，未计入时序解耦价值，正在重新评估（§7）。

## 4. 实测指标

单独报告任一指标均易失真；链路的可用性由最弱的一项决定，故四项并列。

### 4.1 算力基线

对同一算法（陷波 + 低通，Q2.14）实现四种版本，5000 个样本的实测结果：

| 实现 | 吞吐量 | 可否实时流式 |
|---|---|---|
| 浮点逐样本（参考） | 0.80 MS/s | 可 |
| 频域批处理（FFT） | 9.3 MS/s | **不可**（需完整记录，边界误差 524 LSB） |
| **定点逐样本**（实时软件实现的真实成本） | 0.90 MS/s | 可 |
| **RTL 流水线** | **62.5 MS/s** | 硬件 |

RTL 相对可实时运行的软件实现提速 **70 倍**；相对最快的离线方法提速 6.8 倍，
但后者不具备流式能力，且其循环卷积边界误差为定点误差的 314 倍。

计时在 PC（Intel i7-1165G7）上完成；目标平台为 ARM Cortex-A9，纯 Python 循环预计慢 5~10 倍，
故上述加速比属保守估计。

### 4.2 数值精度

| 对比 | 最大误差 | RMS 误差 |
|---|---|---|
| 定点 vs 浮点 | 1.67 LSB（满量程 0.041%） | 0.49 LSB |
| **RTL vs 定点模型** | **0 LSB（2000/2000 逐位相同）** | 0 |

"逐位相同"的意义在于将 RTL 实现与算法设计解耦：此后修改定点模型即可确定 RTL 是否正确，
无需重新论证算法本身。

### 4.3 时间基准

| 采样实现 | 实际采样率 | 均值误差 | 抖动（std） |
|---|---|---|---|
| `time.sleep(4 ms)` | 236.52 Hz | +5.70% | 335 µs |
| `time.perf_counter` 忙等 | **250.00 Hz** | **+0.00%** | **3.9 µs** |

采样率偏差 5.70% 时，50 Hz 干扰在滤波器视角下偏移至 52.85 Hz，超出陷波 −3 dB 带宽，
抑制功能失效。该项指标是滤波功能生效的前置条件。

### 4.4 生理量正确性

以合成信号注入已知参数，检验算法能否还原：

| 参数 | 实测 | 验证方式 |
|---|---|---|
| HR | 71.97 BPM（真值 72） | R 峰 71/71 检出 |
| HRV | SDNN 26.9 ms / RMSSD 25.0 ms | 注入已知心率变异 |
| **呼吸率（EDR）** | **12→11.8 / 15→15.0 / 18→18.2 次/分** | **注入已知呼吸频率** |

判据为呼吸率误差 < 0.5 次/分，实测最大误差 0.2 次/分。
该判据在开发过程中检出一处算法缺陷，详见 §5.5。

### 4.5 资源与延迟

| 资源 | 用量 | 占比 |
|---|---|---|
| LUT | 3008 / 53200 | 5.65% |
| FF | 3480 / 106400 | 3.27% |
| BRAM | 2.5 / 140 | 1.79% |
| DSP48 | 23 / 220 | 10.45% |
| **时序** | **WNS +0.945 ns，TNS 0，失败端点 0** | — |
| 流水延迟 | 96 ns（6 拍） | 占 4 ms 采样周期的 0.0024% |

时序约束按 10 ns 施加，实际时钟周期为 16 ns，故真实时序余量约 6.7 ns。

### 4.6 系统级能力（2026-11-04 新增）

前三项是"链路指标"，这一项是"系统能做什么"。四个能力全部在板上实测：

| 能力 | 实现层 | 实测结果 |
|---|---|---|
| **SQI 信号质量** | 硬件（PL） | 不注入：等级 **3**、能量保留 **98.7%**；注入 50 Hz：等级 **1**、保留 **39.0%** |
| **HRV 心率变异性** | 硬件累加 + PS 开方 | n=64、剔除 0、**mean=103.5000**（理论 2³²/(166×250000)=103.49） |
| **AXI-Stream 采样流** | PL → DMA | 500 样本连续恢复，峰值 **4095**（12 位满量程），波形完整无缺 |
| **实时波形显示** | PS（串口） | 心率 **75.0 BPM**、质量 **3/3**、幅度 **1999**，2.5 秒窗口滚动刷新 |

**SQI 的意义**：设备自己知道"这段数据可不可信"。项目开发过程中曾四次把噪声
误判为心电信号，这正是质量评估存在的理由——不是锦上添花，是防止错误结论的前提。

**HRV 的实现取舍**：硬件只做累加（n / Σrr / Σrr² / ΣΔrr²），开方与除法留给 PS。
理由是每次心跳才更新一次（间隔 3.2M 个时钟），硬件开方占一条长进位链却无实时收益。

**DMA 的价值不在带宽**：原始波形仅 500 B/s，DMA 的意义是把**采样时刻的控制权**
从软件循环交还硬件时钟——实测 `time.sleep(4ms)` 造成 5.70% 采样率偏差，
足以让 50 Hz 陷波完全失效。
## 5. 关键设计判断

以下五项均伴随测量证据，且各自对应一次对初始方案的修正。

### 5.1 放弃 0.5 Hz 数字高通：功能在模拟域与软件域重新分配

初始滤波方案为三级级联（陷波 → 0.5 Hz 高通 → 40 Hz 低通），其中高通用于抑制基线漂移。

实测表明该结构在 16 位字长下不可实现：0.5 Hz 高通的极点半径为 0.9911，
导致 `A(1) = 1 + a1 + a2 = 1.565e−4`，输出量化误差经反馈环放大 **6389 倍**。
四种实现方式的实测误差如下，判据为 2 LSB：

| 实现 | 输出误差 |
|---|---|
| 16 位截断 | 3198 LSB（发散） |
| 16 位四舍五入 | 729 LSB |
| 内部 Q14 精度 | 17 LSB（乘法器需 26 位，资源不可接受） |
| 改一阶 DC 阻断 | 140 LSB |

**结论**：不再寻求该结构的实现方式，而是重新分配功能域——基线漂移改由模拟前端的高通特性、
PT 内部的 5~15 Hz 带通、以及 PS 侧软件去基线三者共同承担。

该判断的意义在于：识别出某结构在给定字长下不可实现，比强行实现更有价值；
功能不必全部由 PL 承担，这是软硬件划分的核心内容。

### 5.2 板级时钟为 62.5 MHz：配置值不等于运行时值

Block Design 中 `FCLK_CLK0` 配置为 100 MHz，时序约束与分频参数均据此设定。

一次"检测器漏拍"异常促使对该前提进行核验，三个与 PYNQ 无关的独立量给出一致结论：

| 证据 | 导出值 |
|---|---|
| `Clocks.fclk0_mhz` 读数 | 62.5 MHz |
| 20 秒内检测数 1→16（44.95 BPM） | 采样率低于预期 |
| 每拍 206.5 点 ÷ 1.335 s | 约 154.7 Hz，对应 fclk 约 61.9 MHz |

根本原因：PS 侧的 FCLK 由 `BOOT.BIN` 内 `ps7_init` 在启动时写寄存器确定，
`.bit` 文件不改变 PS 时钟，因此 Block Design 中配置的 100 MHz 从未在运行时生效。

修正措施：`TICK_DIV` 由 400000 改为 250000，板端所有频率字重算（72 BPM：52 → 83）。

该判断的意义在于：一个未被核验的前提会派生出多个自相矛盾的现象
（"漏拍""高心率档失锁""RR 不更新"实为同一根因）。

### 5.3 可观测性优先于修改逻辑

Pan-Tompkins 检测数停滞于 3，该现象可解释为检测链失效、漏检、或阈值失配，三者的修改方向互斥。

处理方式为引入两级观测手段，而非直接修改算法：

1. 将 PT 内部的滑动和写入波形缓冲的调试通道，由 PS 回读 → 得到 `max = 395139`，
   每个 QRS 处存在清晰峰值，间隔约 206 点，**证明前端滤波链正确**；
2. 在检测时刻将 `0x8000 | r_index` 写入缓冲 → 证明**每一拍均被检出**，
   `r_index` 与黄金参考（83/289/496/702）偏差不超过 1。

两级观测将问题从"算法错误"定位至"时基错误"，即 §5.2。

该判断的意义在于：可观测性的实现成本（十余行 RTL）远低于盲改，且结论可复核。

### 5.4 串行 MAC：以时间预算换取面积

Pan-Tompkins 的带通环节需要 61 抽头 FIR。并行实现的综合结果为 **WNS −98 ns**，无法收敛。

依据是该采样率下时间资源极度富余：

```
每样本可用时钟数 = 62.5 MHz / 250 Hz = 250 000
串行 MAC 占用     = 128 拍 / 样本
时间预算占比      = 128 / 250000 = 0.051%
```

改串行 MAC 后 DSP 由 61 降至 4，时序收敛。

该判断的意义在于：在低采样率的生物电信号处理中，"慢"是可交换的资源，
以时间换面积是本类设计的主要优化手段。

### 5.5 测量方案本身需要设计：抑制比由 −3.4 dB 修正至 −68.5 dB

板级首次实测的 50 Hz 抑制比为 −3.4 dB，与仿真预期（−39.6 dB）相差 12 倍。
先后提出三种解释，前两种被数据否定：

| 假设 | 验证方式 | 结论 |
|---|---|---|
| 环形缓冲未刷新（2.5 s < 4.096 s） | 等待时间改为 5.0 s 后重测 | 否证（298.1 / 202.38 LSB，无明显变化） |
| 注入幅度仅为寄存器值的一半 | 以纯正弦检验测量函数 | 否证（输入 600 LSB，测得 600.3 LSB） |
| 心电峰值 2047 与注入 600 相加后饱和削顶 | 关闭心电（`FTW = 0`）仅保留纯正弦 | 成立 |

根因由三个测试缺陷叠加构成：

1. 心电峰值已达 12 位正极限，叠加 600 LSB 后产生饱和削顶，被测对象不再是正弦；
2. R 波为窄脉冲，其频谱泄漏至 50 Hz 附近，掩盖真实的 50 Hz 残余；
3. 环形缓冲窗口未覆盖完整周期。

修正测试条件后，实测抑制比为 **−68.5 dB**（滤波后残余 0.19 LSB，已低于一个量化台阶）。

该判断的意义在于：单频指标的测量必须使用单频激励，且激励幅度需留足裕量；
"测量结果异常"应先核验测量方案，而非修改设计。

## 6. 验证流程

验证分四层，逐层给出判据与命令，任一层的失败均不应向下继续。

| 层 | 操作 | 判据 | 验证内容 |
|---|---|---|---|
| L1 | `vivado -mode batch -source vivado/rebuild_phase1.tcl` → 核验 `.gen` 缓存 → `rebuild_phase2.tcl` | WNS > 0，0 Critical Warning，比特流 MD5 更新 | 可综合性与时序正确性 |
| L2 | `python sim/filt/compare_rtl.py` | **2000/2000 逐位相同，偏移 +0** | RTL 与定点模型等价 |
| L3 | `python3 /boot/host_ecg.py` | 抑制比 ≤ −20 dB（实测 −68.5 dB） | 外部样本可进入硬件链，陷波有效 |
| L4 | `python python/vitals.py` | 呼吸率误差 < 0.5 次/分 | HR / HRV / EDR 计算正确 |

L1 的核验步骤不可省略：Vivado 的 IP 缓存未失效时会出现"源码已修改、综合仍使用旧 HDL"的情况，
本项目曾因此产生一次无效构建。核验方式为检查
`ecg_system.gen/sources_1/bd/ecg_bd/ipshared/*/hdl/` 是否包含本次修改。

硬件连接（如需接入真实模拟前端）：

| 器件 | 参数 |
|---|---|
| 模拟前端 | AD8232，供电 3.3 V（不可接 5 V，其绝对最大电源为 3.5 V） |
| 分压网络 | 2.7 kΩ + 0.93 kΩ（分压比 0.2562，将 0~3.3 V 变换至 XADC 的 0~1.0 V 量程） |
| 接入端 | 板边 J5 排针，丝印自上而下为 `GND` / `VN` / `VP` |

J5 的丝印顺序与其原理图引脚编号顺序相反，接线须以丝印为准。

## 7. 已知限制与开放问题

| 项目 | 现状 | 原因 |
|---|---|---|
| 真实人体心电波形 | 未取得 | AD8232 输出约 0.23 mV，低于当前噪声水平，前级增益不足 |
| 采样时基 | PS 侧忙等，抖动 3.9~57 µs | 采样时刻由软件循环决定，未做硬件触发采集 |
| AXI-Stream / DMA | 未采用 | 原始波形 500 B/s，DMA 的固定开销高于其吞吐收益；**但该结论未计入时序解耦价值，正在重新评估** |
| HLS | 未采用 | 本设计为固定系数 IIR，手写 RTL 可控性更高；HLS 的价值在于复杂算法的快速迭代 |
| **AXI DMA 内存步长** | 功能可用，但地址步长是 2 倍（每 2 样本占 8 字节） | 流宽 16 / 内存宽 32 的组合下 AXI 互连的实际行为；根治需把流宽改为 32 位 |
| **实时显示** | 串口字符画（79 列） | 板子与笔记本不在同一网段，且经串口连接，浏览器方案不可用 |
| **XADC 过采样** | 脚本就绪，待实验室验证 | 真实心电信号幅度不足（约 24 码 vs 噪声 15 码），需用平均降噪 || 多导联 | 未实现 | 需多路模拟前端，当前硬件仅具备单通道 |

上述条目为设计取舍的记录，非未完成事项的说明。

## 9. 复现步骤（从零开始）

### 9.1 环境

| 项 | 版本 |
|---|---|
| 开发板 | AMD PYNQ-Z2（Zynq-7000 **XC7Z020CLG400-1**） |
| EDA 工具 | **Vivado 2026.1** |
| 板端系统 | PYNQ 2.7（Linux 5.15） |
| 主机 Python | 3.10+（numpy） |

### 9.2 重建硬件

```bash
# 阶段 1：清缓存并综合
vivado -mode batch -source vivado/rebuild_phase1.tcl

# 阶段 2：实现并导出比特流
vivado -mode batch -source vivado/rebuild_phase2.tcl
```

产物：`board/sd_upload/ecg_bd.bit` 与 `ecg_bd.hwh`（两者必须同名同目录）。

> **注意**：`.gen / .runs` 等构建产物已排除在仓库外，必须由上述脚本重建。

### 9.3 部署到板子

1. 把 `board/sd_upload/` 下的全部文件拷到 SD 卡根目录；
2. 插卡上电，串口 115200 连接，登录 `xilinx`；
3. `sudo -s` 后执行验证脚本。

### 9.4 逐项验证（每项都有判据）

| 顺序 | 命令 | 通过判据 |
|---|---|---|
| 1 | `python3 /boot/xadc_selftest.py` | 读到 XADC 通道数据，非 0 / 非 4095 |
| 2 | `python3 /boot/filt_check.py` | 抑制比优于 −60 dB |
| 3 | `python3 /boot/rate_check.py` | 采样率 250.00 Hz，误差 < 0.5% |
| 4 | `python3 /boot/pt_check.py` | R 峰间隔与理论值偏差 ≤ 1 采样点 |
| 5 | `python3 /boot/vitals_check.py` | HRV `n ≥ 60`、剔除 ≤ 5 |
| 6 | `python3 /boot/dma_check.py` | 500 样本连续恢复，峰值接近 4095 |
| 7 | `python3 /boot/term_monitor.py` | 终端出现有节律的心电波形 |

### 9.5 仿真复现

```bash
cd sim/vitals
xvlog ../vitals_hw.v tb_vitals.v
xelab -debug typical tb_vitals -s tb_vitals_sim
xsim tb_vitals_sim -R
```

**通过判据**：输出 `PASS`，且 `n=22`、`sum_rr=4554`、`sum_drr2=0`、`min/max=207`。
