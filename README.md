# ECG-DDS-FPGA

**在 PYNQ-Z2（Zynq-7020）上，从零搭一条可用于真实人体的心电采集与处理链路，
并把它的"速度 / 精度 / 时间基准 / 生理量正确性"四个维度全部量化。**

---

## 0. 一句话说清做了什么

我们在 FPGA 的可编程逻辑里实现了三段硬件：

1. **一个可编程的心电波形源**（DDS + 256 点 P-QRS-T 模板），频率字决定心率，用于在没有任何外部信号源时也能验证整条链路；
2. **一条定点滤波链**（50 Hz 陷波 → 40 Hz 低通，Q2.14 定点，两级 biquad，三级流水），用来压制真实采集里最大的敌人——工频干扰；
3. **一个 Pan-Tompkins 检测器**（串行 MAC 版），把滤波后的波形变成 R 波位置，进而得到心率。

三段之外，还实现了一个**可回读的波形缓冲**、一个**自证身份的版本寄存器**、
以及一条**把外部真实样本灌进硬件链的入口**——后者让 AD8232 采到的人体信号第一次
真正流过我们自己写的 RTL，而不是只在 Python 里做软件滤波。

---

## 1. 为什么做这个

心电信号的两个物理事实决定了这套设计：

- **幅度极小**：体表心电约 0.3~2 mV，而工频干扰可以到几百 mV——**干扰比信号大两个数量级**；
- **频率很低**：QRS 波的能量集中在 5~15 Hz，而 50 Hz 工频正好落在它的旁边。

所以一条可用的心电链路，必须先"把 50 Hz 压下去"，再"把 QRS 找出来"。
这两件事在 PC 上都是一个 `scipy.signal` 调用，但在 FPGA 上，
它们要回答三个工程问题：

| 问题 | 我们的答案 |
|---|---|
| 定点化之后还能保持精度吗？ | 相对浮点最大 **1.67 LSB**（满量程的 0.041%） |
| 流水线能收敛吗？ | **WNS +0.741 ns**，0 违例，且 RTL 与定点模型 **2000/2000 逐位相同** |
| 采样时间基准够准吗？ | 均值误差 **+0.00%**，抖动 **3.9 µs** |

### 2.2 三段硬件各自在干什么

**① 心电波形源（DDS）**

用 32 位相位累加器扫描一张 256 点的心电模板表，频率字 `FTW` 决定心率：

```
每拍采样点数 = 2³² / (FTW × TICK_DIV)        TICK_DIV = 62.5MHz / 250Hz = 250000
FTW = 83 → 206.99 点/拍 → 72.5 BPM
```

**为什么不用"文件回放"**：因为需要**任意心率**。用频率字可以连续扫 72.5→179.9 BPM，
这是"扫频验证"的前提（见 §4.8）。若用文件，改心率就要重做一份数据。

**② 滤波链（ecg_filt）**

两级 IIR biquad 级联，Direct Form I，系数 Q2.14：

| 级 | 作用 | 关键参数 |
|---|---|---|
| 第 1 级 | 50 Hz 陷波 | Q = 10，−3 dB 带宽 48.11~51.91 Hz |
| 第 2 级 | 40 Hz 低通 | Q = 0.707，抑制高频肌电与混叠 |

每级拆 **3 拍流水**（乘法 / 加法树 / 移位饱和），共 6 拍 = 96 ns 延迟。

**③ R 波检测（pt_chain）**

Pan-Tompkins 五步：带通 5~15 Hz → 微分 → 平方 → 150 ms 滑动积分 → 自适应阈值判峰。
其中带通与积分用**串行 MAC** 实现（见 §4.5）。

### 2.3 PS 侧做什么，不做什么

| 做 | 不做 |
|---|---|
| 配置寄存器、读回波形 | **不搬原始数据流**（500 B/s，DMA 不划算，见 §4.9） |
| 计算 HRV（SDNN/RMSSD/pNN50） | 不做实时滤波（那是 PL 的事） |
| 计算 EDR（心电衍生呼吸率） | 不做 R 波检测（那是 PL 的事） |
| 依据信号质量做置信判断 | — |

**分工原则：PL 输出"已降维的特征"（RR、检测数、质量分），PS 只做"决策与统计"。**

## 3. 四个维度，以及它们为什么必须一起看

单独报一个数字很容易好看，但一条链路只以**最弱的那个维度**为准。
所以我们把四个维度全部量化：

### 3.1 算力：快 70 倍

同一算法（陷波 + 低通，Q2.14）的四种实现，5000 点：

| 实现 | 吞吐量 | 能否实时流式 |
|---|---|---|
| 浮点逐样本（参考） | 0.80 MS/s | 可以 |
| 频域批处理（FFT） | 9.3 MS/s | **不可**（需整段，边界误差 524 LSB） |
| **定点逐样本**（实时软件实现的真实成本） | 0.90 MS/s | 可以 |
| **RTL 流水线** | **62.5 MS/s** | 硬件 |

> **RTL 对"能跑在系统里的实时软件"快 70 倍；对最快的离线方法快 6.8 倍，
> 而后者不可流式、边界误差是定点误差的 314 倍。**

⚠️ 计时在 PC（i7-1165G7）上完成，目标板是 ARM Cortex-A9，**真实加速比更大**——这个对比是保守的。

### 3.2 数值精度：1.67 LSB，且 RTL 与模型逐位相同

| 对比 | 最大误差 | RMS |
|---|---|---|
| 定点 vs 浮点 | **1.67 LSB**（满量程 0.041%） | 0.49 LSB |
| **RTL vs 定点模型** | **0 LSB（2000/2000 逐位相同）** | 0 |

**为什么"逐位相同"比"误差小"更重要**：它把"RTL 实现"与"算法设计"彻底解耦——
以后只要改 Python 模型，就能确定 RTL 改得对不对，不需要重新论证一遍算法。

### 3.3 时间基准：误差 0.00%，抖动 3.9 µs

滤波器的频率响应是**以采样率为坐标**的。采样率偏 5.7%，

```
50 Hz 干扰 → 被看成 52.85 Hz → 偏离陷波中心 2.85 Hz
而陷波 −3 dB 带宽只有 ±1.9 Hz → 完全落在带外 → 陷波器形同虚设
```

实测两种采样实现的差别：

| 方案 | 实际采样率 | 误差 | 陷波是否有效 |
|---|---|---|---|
| `time.sleep(4ms)` | 236.52 Hz | **+5.70%** | ❌ **完全失效** |
| `perf_counter` 忙等 | **250.00 Hz** | **+0.00%** | ✅ 正中靶心 |

> **"算得快"不够，"算的时候采样率对"才是前提。**
> 这是本项目实测到的最容易翻车的一环：滤波器写得再对，时基错了就是零。

### 3.4 生理量正确性：注入已知量，看能否还原

| 参数 | 结果 | 验证方式 |
|---|---|---|
| **HR** | **71.97 BPM**（真值 72） | R 峰 71/71 检出 |
| **HRV** | SDNN 26.9 ms / RMSSD 25.0 ms / pNN50 | 注入已知心率变异 |
| **EDR（呼吸率）** | **12→11.8 / 15→15.0 / 18→18.2 次/分** | **注入已知呼吸率** |

**验证方法**：合成心电时注入 0.200 / 0.250 / 0.300 Hz 的呼吸调制，
再让算法去估计。判据：误差 < 0.5 次/分。实测最大误差 **0.2**。

> 不注入真值就没有判据。第一版 EDR 算出来恰好是真实值的 2 倍
> （12→23.8 / 15→30.0 / 18→36.2），正是这个判据把它抓出来的：
> 高通拐点设在 0.3 Hz，把 0.2~0.3 Hz 的**基频滤掉了，只剩二次谐波**。

### 3.5 代价

| 资源 | 用量 | 占比 |
|---|---|---|
| LUT | 1788 / 53200 | **3.36%** |
| FF | 2522 / 106400 | **2.37%** |
| BRAM | 1.5 / 140 | **1.07%** |
| DSP48 | 17 / 220 | **7.73%** |
| **时序** | **WNS +0.741 ns / TNS 0 / 失败端点 0** | 10 ns 约束下收敛 |

实际时钟是 16 ns（62.5 MHz），所以真实时序余量约 **6.7 ns**。

## 4. 九个关键判断（每个都有取舍与被数据推翻的过程）

> 只列有**权衡**和**证据**的判断。教科书式的常识（比如"IIR 比 FIR 省资源"）不占篇幅。

### 4.1 放弃 0.5 Hz 数字高通，把功能重新分工

**冲突**：滤波器原设计是"50 Hz 陷波 → 0.5 Hz 高通 → 40 Hz 低通"三级级联，用来同时去掉工频和基线漂移。

**证据**：0.5 Hz 高通的极点半径 **r = 0.9911**，于是 `A(1) = 1 + a1 + a2 = 1.565e-4`——
这是一个"近乎零"的分母，**输出量化误差会被反馈环放大 6389 倍**。

**四种实现全部实测失败**：

| 做法 | 实测输出误差 |
|---|---|
| 16 位截断 | 3198 LSB（发散） |
| 16 位四舍五入 | 729 LSB |
| 内部 Q14 精度 | 17 LSB（但乘法器要 26 位，资源不可接受） |
| 改一阶 DC 阻断 | 140 LSB |

判据是 2 LSB，**没有一种达标**。

**决策**：不是"再想办法做对"，而是**重新划分功能域**：

| 基线漂移由谁去掉 | 理由 |
|---|---|
| AD8232 模块的硬件高通 | 模拟域，零成本 |
| PT 内部的 5~15 Hz 带通 | 本来就要做，顺手 |
| PS 侧软件去基线 | 只在分析时用，不影响实时 |

**为什么这是对的**：识别出"某个结构在给定字长下根本不可实现"，比硬着头皮做出来更有价值。
**功能不必都放在 PL 里**——这是软硬件划分的核心判断。

### 4.2 不相信文档：板级时钟是 62.5 MHz，不是 100 MHz

**冲突**：BD 里 `FCLK_CLK0` 设的是 100 MHz，所有时序约束、分频参数都按它算。

**证据**：一次"PT 漏拍"的异常，最终用三个与 PYNQ 无关的物理量交叉验证：

| 独立证据 | 推出 |
|---|---|
| `Clocks.fclk0_mhz` 读数 | 62.5 |
| 20 秒内检测数 1→16（44.95 BPM） | 采样率低于预期 |
| 每拍 206.5 点 ÷ 1.335 s | 约 154.7 Hz → fclk ≈ 61.9 MHz |

**根因**：PS 侧的 FCLK 由 `BOOT.BIN` 里的 `ps7_init` 在开机时写寄存器决定，
**`.bit` 不改 PS 时钟**。所以 BD 里那个 100 MHz **从未在运行时生效**。

**影响**：`TICK_DIV` 从 400000 改为 250000，所有板端 FTW 重算（72 BPM：52 → 83）。

**为什么这是对的**：**"配置值"不等于"运行时值"**。
而且一个错误前提会派生多个假问题——"漏拍""180 BPM 卡死""RR 不更新"全是同一个根。

### 4.3 先把内部信号引出来，再动手改

**冲突**：PT 检测数停在 3，现象可以解释为"检测链死了""漏拍""阈值不对"，三种改法完全不同。

**做法**：不猜。临时把 PT 内部的**滑动和**写进波形缓冲的调试通道，Python 回读：

```
max = 395139，每个 QRS 处一个清晰的峰，间隔约 206 点
```

**一眼证明**：前端（带通→微分→平方→积分）完全正确，问题只在判定层。
随后再加一层：检测时把 `0x8000 | r_index` 写进缓冲 → 证明**每一拍都被检出**，
`r_index` 与黄金参考偏差 ≤1。

**为什么要留调试通道**：这个功能只花了十几行 RTL，却把 3 小时的猜测变成 10 分钟的定位。
**可观测性的成本远低于盲改。**

### 4.4 让设计自证身份：VERSION 寄存器

每次改 RTL 都递增一个版本号，Python 上板第一件事就是读它并强校验。

**后来它真的救了一次**：板子上存在两份同名文件——

```
/boot/ecg_bd.bit        → v5 (0xEC600005)   SD 卡 FAT 分区，部署的那份
/home/xilinx/ecg_bd.bit → v2 (0xEC600002)   ext4 根分区的历史遗留
```

脚本用了后者 → 加载旧设计 → 注入器根本不存在 → 缓冲区读回全 0。
没有版本自证，这会被误诊成"寄存器写入失败"或"AXI 坏了"。

### 4.5 串行 MAC：用 0.03% 的时间预算，换 60 个 DSP

**冲突**：PT 的带通需要 61 抽头 FIR。并行实现 = 61 个乘法器 → **WNS −98 ns**，根本收敛不了。

**证据**：采样率只有 250 Hz，每个样本有 `62.5e6 / 250 = 250,000` 个时钟可用。

**决策**：改**串行 MAC**——1 个乘法器轮流算 61 个抽头，约 128 拍/样本。

```
占用时间预算 = 128 / 250000 = 0.051%（实际按 400000 算也只有 0.03%）
资源：DSP 61 → 4
```

**为什么这是对的**：**在采样率极低的应用里，"慢"是免费的资源**。
把慢换成面积，是这类生物电信号处理的核心杠杆。

### 4.6 定点格式由系数的动态范围决定，不由习惯决定

**冲突**：定点系数默认用 Q1.15（范围 ±1）。

**证据**：0.5 Hz 高通的 `b1 = -1.9823`，**超出 Q1.15 的表示范围**，
被**静默截断**成 −1.0——误差 0.98，滤波器彻底失效，**而且不报任何错**。

**决策**：改 Q2.14（±2，分辨率 1/16384），代价仅 0.34 dB。

**为什么这是对的**：**静默失效比报错更危险**。
选定点格式的依据是"这批系数的实际取值范围"，不是"大家都在用 Q1.15"。

### 4.7 测量本身就是设计的一部分

**冲突**：板级实测抑制比 **−3.4 dB**，而仿真预期 −39.6 dB，差 12 倍。

**三次假设，前两次都被数据推翻**：

| 假设 | 验证 | 结果 |
|---|---|---|
| 环形缓冲未刷新（2.5 s < 4.096 s） | 改 5.0 s 重测 | ❌ 298.1 / 202.38，几乎没变 |
| 注入器幅度只有一半 | 用纯正弦验证测量函数 | ❌ 600 输入测出 600.3，函数正确 |
| **R 波 2047 + 注入 600 饱和削波** | 关掉心电（FTW=0）只留纯正弦 | ✅ **成立** |

**根因**：三个测试缺陷叠加——

1. 心电峰值已达 12 位上限，再叠加 600 LSB 注入 → **饱和削顶**，被测对象已不是正弦；
2. R 波是窄脉冲，其**频谱泄漏到 50 Hz 附近**，把真实的 50 Hz 残余淹没；
3. 环形缓冲窗口未覆盖完整周期。

**修正后**：把心电关掉单独测 → **−68.5 dB**（滤波后只剩 0.19 LSB，已低于 1 个量化台阶）。

**为什么这是对的**：**"测出坏结果"先怀疑测量，别急着改设计。**
用纯正弦验证测量函数本身（成本 1 分钟），能立刻排除一半假设。

### 4.8 用"扫频"而不是"单点"验证检测器

**冲突**：单点测 72 BPM 通过，不代表检测器可用。

**做法**：板上扫 `FTW = 83/104/124/166/206`（对应 72.5~179.9 BPM），每档 4 秒，
同时对比三路数据：PT 的 RR / 旧检测器的 RR / 理论值 `2³²/(FTW×250000)`。

| FTW | 83 | 104 | 124 | 166 | 206 |
|---|---|---|---|---|---|
| 理论 | 206.99 | 165.2 | 138.5 | 103.5 | 83.4 |
| PT 实测 | **207** | **165** | **139** | **104** | **84** |

全档误差 ≤1 采样点。

**顺带纠正一个误判**：此前认为"180 BPM 卡死"，
实际是**切档后自适应阈值（spki/npki）重收敛的瞬态**——只等了 3 秒就下结论。
**自适应算法的切换响应不能当作缺陷。**

### 4.9 不给 500 B/s 的数据配 DMA

**冲突**：技术栈清单里"AXI-Stream + DMA"是加分项，我们一个都没用。

**证据**：

```
ECG 采样率 250 S/s × 2 字节 = 500 B/s
DMA 单次传输的设置 + 中断开销 = µs 级
```

**用几十微秒的固定开销去搬 2 个字节，是负优化。**

**决策**：保持 AXI-Lite 寄存器访问，改在 **PL 里做数据缩减**——
不把原始波形搬给 PS，而是直接输出 **RR 间隔、检测次数、信号质量分**。

**为什么这是对的**：
评分要求"合理使用片上资源，**避免以显著的资源代价换取有限的性能收益**"。
这里加 DMA 是满足清单，不是解决问题。
**能说清"为什么不用"，比堆砌技术栈更能体现工程判断。**

## 5. 验证路径：从零到看见第一个结果

不是"快速开始"，而是**四层验证**，每层一条命令、一个明确的判据。

| 层 | 命令 | 判据 | 证明什么 |
|---|---|---|---|
| **L1 设计能收敛** | `vivado -mode batch -source vivado/rebuild_phase1.tcl` → 确认 `.gen` 缓存已更新 → `rebuild_phase2.tcl` | WNS > 0、0 Critical Warning、新 MD5 | RTL 可综合、时序正确 |
| **L2 算法等价** | `python sim/filt/compare_rtl.py` | **2000/2000 逐位相同，偏移 +0** | RTL 与定点模型等价 |
| **L3 上板通路** | `python3 /boot/host_ecg.py` | **A3 ≤ −20 dB**（实测 −68.5 dB） | 外部样本能进硬件链、陷波有效 |
| **L4 生理量正确** | `python python/vitals.py` | 呼吸率误差 **< 0.5 次/分** | HR/HRV/EDR 算得对 |

> **L1 有个强制校验**：phase1 之后必须确认
> `ecg_system.gen/sources_1/bd/ecg_bd/ipshared/*/hdl/` 已是新代码。
> Vivado 的 IP 缓存不失效，会导致"源码改了、综合却用旧 HDL"——本项目踩过这个坑。

硬件连接（如果要接真实前端）：

| 件 | 参数 |
|---|---|
| 模拟前端 | AD8232（3.3 V 供电，**不可接 5 V**） |
| 分压 | 2.7 kΩ + 0.93 kΩ（÷3.90，把 0~3.3 V 压到 XADC 的 0~1.0 V） |
| 接入点 | 板子下边缘 J5 排针，丝印自上而下 **`GND` / `VN` / `VP`** |

> ⚠️ **必须按丝印接，不能按脚号接。** J5 的丝印顺序（GND/VN/VP）与原理图的引脚编号顺序相反，
> 这是本项目用实拍照片 + 丝印比对才确认的。

## 6. 诚实的边界

| 限制 | 现状 | 原因 |
|---|---|---|
| **真实心电波形** | 未采到 | AD8232 输出约 0.23 mV，低于当前噪声；前端增益不足 |
| **采样由软件驱动** | 250 Hz 闭环忙等 | 未做硬件定时采集（见 §4.9 为何不加 DMA） |
| **技术栈覆盖** | 全程 AXI-Lite | 未用 HLS / AXI-Stream；理由见 §4.9 |
| **时基抖动** | 3.9~57 µs | Linux 调度抢占，非代码问题 |
| **HLS** | 未使用 | 本项目算法为固定系数的 IIR，RTL 手写更可控；HLS 的价值在快速迭代复杂算法 |

**这些不是"没做完的借口"，而是"做过取舍的记录"。**
